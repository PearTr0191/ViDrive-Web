How to read this report

Two disciplines are covered because they now overlap but are not the same thing. Knowing the difference tells you which fix to prioritize.

SEO — be indexed & ranked

Search Engine Optimization is about crawlers, rendering, links, and relevance signals so a page earns a spot in a results list. The boss is Googlebot (and Bingbot). The scoreboard is rankings, impressions, clicks.

Key idea: if a bot can't read your <title>, your headings, or your URLs, nothing else matters. That makes technical foundations the gate before content.

AEO — be the answer

Answer Engine Optimization is about being the cited source inside an AI-generated answer (Search Generative Experience, ChatGPT, Gemini, voice assistants, Perplexity). The boss is the LLM retriever.

Key idea: LLMs don't "rank a page" the way Google does. They extract facts. They love structured data, clean definitions, Q&A, tables, and clear entity names. AEO is SEO's factual, machine-readable layer.

The one sentence that frames every fix below

Google needs to find and understand you; answer engines need to trust and quote you. Technical SEO gets you into the candidate set; structured data + authoritative, well-sourced content gets you cited. Do both, in that order.

Each finding card below uses the same anatomy so you can skim: severity → The principle (the rule + why) → What we found (real repo evidence) → The fix (concept + code) → Prompt an agent (copy-paste) → optional AEO angle…

Technical foundations — the gate

Before any content heroics: crawlers must be able to read your titles, follow your links, and not hit dead ends. A Vite React SPA is render-on-client, so these are exactly the traps that bite SPAs at launch.

CRIT

1 · No per-route meta management — every page shares one title & description

▶
The principle

The <title> and <meta name="description"> are the two highest-leverage on-page signals. They must be unique per URL and describe that URL's content. In a client-rendered SPA, the document <head> is built once in index.html and never changes on navigation — so all 12 routes broadcast the same title.

What we found

frontend/index.html hardcodes a single title. No head library is installed (npm ls shows no react-helmet, @unhead/react, etc.). The router just swaps components inside #root.

frontend/index.html:12-13 <title>ViDrive — Tính chi phí sở hữu ô tô</title> <meta name="description" content="Công cụ tính phí lăn bánh, khấu hao ... Car TCO & depreciation calculator."> frontend/src/App.tsx:63-75 <Routes> swap <Landing/> etc. — nothing touches document.head
The fix

Add @unhead/react (the React-19-friendly successor to react-helmet, tiny, SSR/CSR-safe). Wrap the app in <UnheadProvider> and call useHead() in each page with its own title/description. Centralize defaults in a usePageMeta() hook so titles stay consistent ("{Page} · ViDrive").
